Asked after r5 (same class as r4): is the design itself weak, and would a structural design close the class instead of a longer checklist? Prompt asked for a design only, no edits. HEAD a131c795. Reviewer output follows (paths made relative). Owner decisions are listed at the end.

## Result

**Yes. B7 has a design weakness. I recommend one transaction owner per document session, with private copy-on-write drafts for vector edits and one model-owned, versioned selection.** A reader should be able to render halfway through a delete and see the complete preceding revision. A failed delete should have nothing to restore in the published document.

### 1. Why r4 recurred

**The implementation gap** is visible in the order of operations. `commit_delete` writes `model.doc`, pumps at T1, installs the index, and only then registers `lease.undo_write`. An earlier exception takes an inner rollback path. Meanwhile, the controller captures the after-image and calls `record()`, which advances history before `write_transaction` rebinds the index. A lease spans these operations, but no single operation publishes them. [commit.py:185](model/vector_paths/commit.py:185) · [commit.py:237](model/vector_paths/commit.py:237) · [pdf_controller.py:5372](controller/pdf_controller.py:5372) · [pdf_model.py:4411](model/pdf_model.py:4411)

**The design gap** is that r4 called for one owner without specifying what other code must lose access to. `model.doc` still hands out a mutable handle. The view keeps an actionable selection token. The window registry can remove a context independently of session release. A new reader, menu action, or promotion path can therefore violate the invariant without touching the transaction code. The serial comparison improved detection, but its observer covers one page’s streams and active history, and it skips intermediate yields. ### 2. The ownership boundary

| Design | What it guarantees and what it costs |
|---|---|
| **A. Private document draft** | A writer opens a private document from the published revision’s immutable bytes. T0, mutation, T1, after-capture, history preparation, and index preparation all happen privately. Failure discards the draft. Readers can continue using the published revision throughout. The cost is a whole-document serialization/reopen, native allocations, and overlapping lifetimes for old and new handles. |
| **B. Single owner with revision-stamped reads** | Necessary under either storage strategy. A render, index request, or process job obtains its source and stamp from the same read. With an **in-place** writer, even a perfect stamp cannot retract pixels already displayed. This alternative must defer reads centrally, wait for outstanding readers before mutation, and own verified rollback. It preserves file-backed handles but makes recovery and UI responsiveness harder. |
| **C. Model-owned selection** | Necessary under either transaction strategy. Store one immutable selection containing session, document revision, page, index identity, mask, and a monotonic selection revision. The action token is model-issued. Document revision alone is insufficient because two clicks can occur on the same document revision. The existing presentation DTO is a suitable starting point. [pdf_model.py:4662](model/pdf_model.py:4662) · [vector_selection_dto.py:36](utils/vector_selection_dto.py:36) |

**Use A behind B, with C, for B7.** The owner prepares one published value containing the handle and backing bytes, handle generation, content revision, history stacks and saved marker, derived index, selection, OCR proof epoch, and edit/secure-save bookkeeping. On the GUI thread it checks the originating session lifetime, base revision, and selection token, then assigns that value once. Allocation, verification, history trimming, and index warming happen before assignment. Refresh, queue processing, and retirement happen afterward. Today’s `doc` setter and `record()` both change externally visible state and cannot serve as preparation methods. [pdf_model.py:899](model/pdf_model.py:899) · [edit_commands.py:1465](model/edit_commands.py:1465) · [pdf_model.py:5012](model/pdf_model.py:5012)

**Give readers a scoped read of one revision.** Render, index, and worker-snapshot APIs return values derived from that revision. Workers receive bytes and a stamp. Cache installation checks that stamp. Keep an old handle alive until its last read finishes, then retire it. Existing mutable-handle holders, including the text engine, must be confined to the owner or reacquired per revision. Every writer reachable during B7 must use owner admission. Otherwise the published handle can still change underneath a read. [engine.py:105](model/text_commit/engine.py:105) · [pdf_controller.py:1219](controller/pdf_controller.py:1219) · [pdf_model.py:5457](model/pdf_model.py:5457)

**One measured qualification changes the design.** On PyMuPDF **1.27.1**, serializing `cad_vector/before.pdf` with the repository’s in-memory snapshot helper changed the **source handle’s trailer `/ID`**, although the normalized digest still matched. Freeze backing bytes when establishing a published revision. Open drafts and serve worker snapshots from those bytes. Run serialization on a private handle before publication. The digest intentionally excludes `/ID`, so it cannot establish that capture was side-effect-free. **CAD cost and save compatibility.** On `hvac-dwg.pdf` (36.5 MB, 50 pages, 10,680 xrefs), one in-memory run took **132 ms** for before-serialization, **2.3 ms** to open the clone, and **102 ms** for after-serialization following a metadata edit. With the old page and both byte buffers retained, peak process commit reached **188 MiB** from a **50 MiB** baseline. B7 already pays for before/after snapshots, so reuse those bytes. These figures exclude vector planning, both integrity passes, and UI refresh. On the small fixture a held page continued reading its original document across the draft edit and became unusable after explicit parent close. Give every new handle a fresh handle generation. A stream-opened clone reported `can_save_incrementally() == 1` in the probe, yet incremental save rejected it with `incremental needs original file`. Vector delete already sets the secure-save latch. Extending cloning to ordinary edits would affect an existing incremental/signature-preserving save path and needs a separate decision. Retain writer and lifecycle admission, stale-result rejection, and integrity verification. **Require the observed execution trace to match an independently specified legal serial execution.** In two real windows, derive the relevant receivers from production registrations and require an acknowledgment from each actual signal, timer, worker bridge, process reply, or handoff source. Deliver at intermediate **and** final T0/T1 yields. Record what was painted, indexed, cached, or released at delivery time. A transient wrong frame followed by a correct final frame must fail. The existing test calls the receiving controller directly for handoff and inventories enclosing `singleShot` functions.
