## Goal

Make the desktop app measurably faster on, in priority order: (1) startup to first window,
(2) open to first rendered page, (3) zoom in continuous mode, (4) scrolling a long document,
(5) tab switching. Every fix is proven by a before/after benchmark; text-edit/commit paths
are out of scope.

## Modules

- Candidates (to be confirmed by profile): `controller/pdf_controller.py`
  (`change_scale`, `_rebuild_continuous_scene`, `_render_active_session`, render scheduling),
  `view/pdf_view.py` (`initialize_continuous_placeholders`, `_on_scroll_changed`,
  `_scene_y_to_page_index`, `_resize_event`), `main.py` import path.

## Steps

1. Harness + BEFORE numbers (N >= 5, median + p90 per scenario).
2. cProfile (main thread) + `-X importtime` for startup.
3. Per hotspot: failing behavioural test -> smallest fix -> re-benchmark (A/B against the
   baseline snapshot, interleaved) -> keep only if the median improves beyond the spread.
4. PITFALLS entry per root cause + index regen; ARCHITECTURE if structure/API moves.
5. `scripts/run_suite.py` once at the end; `ruff check .`.

## Decisions

- Measurements are wall-clock medians across child processes; acceptance tests are
  behavioural (call counts / state), scaling guards use the 4x-input < 8x-time linear guard.
- The venv is Python 3.12, whose cProfile (sys.monitoring) also records worker-thread frames;
  read profiles knowing worker render time (thumbnail / page workers) is mixed in, and use the
  harness's wall-clock scenarios + counters for attribution.
- Isolated A/B pairs for B, D and E were measured on trees that still contained A; the shipped
  proof is the composite `final2` + `final3` (baseline vs B-E).
