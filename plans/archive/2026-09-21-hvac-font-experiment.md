# HVAC PDF：10 處可重現字型實驗

## 目標與範圍
依使用者修正，使用 PyMuPDF 實際修改 10 處文字，保留原字型外觀，保存前後影像與可執行步驟。此階段不改正式編輯器、不把商業軟體操作當成果，不覆寫原始 PDF。

## 檔案與步驟
- `scripts/experiment_hvac_font_edits.py`：固定樣本、CID 字形預檢、原內容串流局部替換、存檔重開驗證與影像證據。
- `output/pdf/manual-font-study/`：測試 PDF、逐處對照圖與 JSON 記錄。
- `docs/experiments/2026-09-21-hvac-font-edits.md`：操作結果、可整合函式與限制。

- [x] 驗證替換文字、原字型資源、文字狀態、非目標區域像素及存檔重開。
- [x] 目視檢查 10 處；對照現有引擎拒絕原因；全樹 lint 通過，相關 157 項測試通過。

## 決策與失敗路徑
- 自家 UI 初步操作曾讓文字消失，已復原；不能把該次當成功。
- PDF-XChange 操作偏離使用者要能整合程式的目的，已停止，不計入 10 處。
- 來源含 Identity-H CID、旋轉、非等向縮放與鏡射；保留原字型及矩陣，避免用抽取的單一字級重建。
- TypeSafe Jev 文字介面不能驗證影像；不以其輸出代替 render 證據。
- 完整 save 會正規化物件 dictionary key 排序；改用副本增量存檔。增量多出 1 個 /XRef stream 屬預期行為。
- `get_texttrace` 可能把多個 Tj 合為同一 trace；使用文字子序列與 origin 聯合定位，不能假設一個 trace 等於一個 show。
- 完成：10 筆已存檔、重開、逐處目視；3 個修改頁的目標區域外差異均為 0；10,676 個非目標既有物件一致。自家 UI 可開啟成品；產品 engine 仍有拒絕，列為後續事項。
